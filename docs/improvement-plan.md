# API — Improvement & Growth Plan

> Package: capell-app/api · Kind: package · Tier: premium · Product group: Capell Publishing Pro · Bundle: publishing-pro · Status: Draft

## 1. Snapshot

`capell-app/api` is a single-surface (frontend) package that exposes one public, read-only JSON endpoint — a page resolver — mapped to two route names (`capell-api.pages.resolve` and the versioned `capell-api.v1.pages.resolve`) in `routes/api.php`, both pointing at the invokable `ResolvePageController`. It owns no models, migrations, or settings (`capell.json` → `database.migrations: false`); all domain logic is delegated to core/layout-builder Actions: `Capell\Core\Actions\ResolvePublicPageByUrlAction`, `Capell\Core\Actions\LoadSiteDomainFromUrlAction`, and `Capell\LayoutBuilder\Actions\BuildPublicLayoutGraphAction`. Its own code is just the controller, an HTML-sanitizer trait (`src/Support/SanitizesPublicHtml.php`), a service provider that registers config + a per-IP rate limiter, and a near-empty health-check class. Current marketplace summary (verbatim): **"Public JSON delivery of published Capell page data."** — identical to `description`, `marketplace.summary`, and the composer `description`. Screenshots declared in `capell.json`: **1** (`docs/assets/marketplace/extension-card.jpg`, a generic card image) — but `docs/screenshots.json` plans **4** capture entries (success, not-found, forbidden, layout) that are not yet reflected in the manifest, a mismatch.

## 2. Improvements (existing functionality)

Prioritized.

1. **Health-check class is a stub — implement real probes or drop the manifest claims.** `capell.json` advertises three `healthChecks` (`api.v1.route`, `api.middleware.config`, `api.cache.headers`, one `critical`) all bound to `Capell\Api\Health\ApiHealthCheck`, but that class only implements `compatibleCapellApiVersion()` (the `ChecksExtensionHealth` contract extends `ExtensionContribution`, whose sole method is version compatibility — see `vendor/capell-app/core/src/Contracts/Extensions/ExtensionContribution.php`). Nothing executes a runtime probe; `AuditExtensionContractsAction` only validates the class exists and is API-compatible. The advertised checks ("V1 route is registered", "responses expose version and cache-tag headers") never actually run. Either implement check methods keyed by `api.v1.route` / `api.middleware.config` / `api.cache.headers`, or reduce the manifest to the checks the contract can support. — `src/Health/ApiHealthCheck.php`, `capell.json:56-78` — **M**

2. **`manifest.performance.cacheTags` (`["api","api:pages"]`) does not match emitted headers.** The controller emits `X-Capell-Cache-Tags` as `api,site:{id},language:{id},page:{id}` (`ResolvePageController::cacheTags()`), never `api:pages`. Downstream cache invalidation that keys off the manifest tag list will miss. Align the manifest `cacheTags` with the real per-request tag scheme (or document that the manifest list is the coarse invalidation surface and add `api:pages` to the response, whichever is intended). — `src/Http/Controllers/ResolvePageController.php:84,127-140`, `capell.json:47` — **S**

3. **`max_candidate_sites` validation rejects legitimate `0` by silently forcing 50.** `candidateSiteLimit()` treats any non-positive or non-numeric value as `50`. A host that sets `0` to disable host-based resolution gets `50` instead — surprising. Clamp explicitly and document that the floor is `1`, or honor `0` as "disabled". — `src/Http/Controllers/ResolvePageController.php:449-458` — **S**

4. **Field projection is hardcoded; `meta` is the only extensible-shaped field but the allow-list is closed.** `DEFAULT_FIELDS`/`ALLOWED_FIELDS` are class constants (`url,title,content,meta`). Page types that expose additional public fields cannot surface them without editing this controller. Introduce an extension point (a registry or a Data contract on `PublicPageFieldsData`) so page-type packages can register additional public-safe fields, consistent with the Capell "register your contribution" pattern. — `src/Http/Controllers/ResolvePageController.php:37-39,258-280` — **M**

5. **`packageIsInstalled()` runs an un-cached DB query on every request when the in-memory flag is absent.** The fallback queries `CapellExtension` (status + `marketplace_runtime_allowed`) per request, swallowing all `Throwable` to `false`. For a public endpoint with a 20ms frontend render budget (`capell.json` `frontendRenderBudgetMs: 20`) this is an avoidable round-trip; cache the installed/enabled decision (short TTL or request-scoped memo) and narrow the catch from `Throwable`. — `src/Http/Controllers/ResolvePageController.php:142-157` — **S**

6. **No `Content-Type`/charset assertion or explicit `Cache-Control` on responses.** Responses rely on Laravel's `response()->json()` defaults. For a public delivery surface, add an explicit `Cache-Control` policy (the manifest declares `cacheSafety.cacheable: false`, so `no-store`/`private` should be asserted on the wire) and a `Vary` header reflecting `variesBy: ["site","locale"]`. Today nothing stops a shared CDN from caching a site-specific body. — `src/Http/Controllers/ResolvePageController.php:116-122`, `capell.json:48-54` — **S/M**

7. **Sanitizer allows only `class` attribute globally and is recreated per controller instance.** `SanitizesPublicHtml` hardcodes `allowAttribute('class','*')` and `allowSafeElements()`. `id`, `data-*`, `aria-*`, `target`/`rel` on links are stripped — likely fine for safety but lossy for headless renderers that need anchors/ARIA. Make the allowed-attribute set config-driven (still safe-by-default) so integrators can opt into `id`/`aria-*` without forking. The loop `foreach (['class'] as $attribute)` is also a one-element loop that should just be a direct call. — `src/Support/SanitizesPublicHtml.php:42-52` — **S**

## 3. Missing Features (gaps)

Tied to `capabilities: ["public-page-api","public-page-api-v1"]` and API-platform norms.

- **Token auth + scopes (table-stakes, currently absent).** The only auth path is Laravel signed URLs for `site`/`language` overrides (`hasValidContextSignature`). There is no API-token (Sanctum) mode for trusted server-to-server consumers, and no scopes. The manifest declares no `permissions[]`. Signed URLs are fine for embedding but awkward for backend integrations that want a long-lived credential. Add an optional `auth_middleware` recipe with Sanctum abilities (`api:read`, `api:layout`).
- **Pagination / collection endpoints (gap).** Only single-page _resolve-by-URL_ exists. There is no "list published pages", "list by site", or "changed since" endpoint — a hard blocker for static-build / incremental-regeneration consumers (a use case the `overview.md` explicitly names: "static build systems"). This is the biggest differentiator gap.
- **Filtering / querying (gap).** No filtering by page type, tag, published-at range, or path prefix. Resolver only accepts an exact `url`.
- **OpenAPI / machine-readable schema (table-stakes).** Contract is documented only in prose (`docs/page-api.md`). No OpenAPI/JSON-Schema artifact, so consumers cannot generate typed clients — `overview.md` "Feature Suggestions" even asks for this. Ship an OpenAPI 3.1 spec generated from the route + field allow-list.
- **Webhooks / change notifications (differentiator).** No push surface; consumers must poll. A "page published/updated" webhook (driven by core lifecycle subscribers) would make the package genuinely headless-CMS-grade.
- **ETag / conditional requests (table-stakes for a read API).** No `ETag`/`If-None-Match` or `Last-Modified`/`If-Modified-Since`. Cheap to add (hash of the resolved payload or page `updated_at`) and meaningfully cuts bandwidth for polling clients.
- **CORS (gap for browser consumers).** The README pitches "lightweight client-side content fetches" and "terms pop-ups", i.e. browser `fetch()` from another origin — but no CORS handling is shipped or documented. Without it, the headline use case fails cross-origin. Provide a documented `middleware` recipe or first-class CORS config.
- **Idempotency / versioning headers (partial).** Versioning exists via `X-Capell-Api-Version: v1` and a `/v1/` route, which is good. But there is no deprecation/sunset header strategy for the legacy unversioned route, and no `v2` extension path beyond a hardcoded `API_VERSION` constant.
- **Rate-limit response headers (gap).** A limiter is registered (`capell-api`, per-IP) but it is **not wired into the default route middleware** (`config.public_pages.rate_limit_middleware` defaults to `null`). Out of the box the public endpoint is unthrottled; the limiter only activates if the host opts in. Also no `X-RateLimit-*`/`Retry-After` documentation. (See also §4.)

## 4. Issues / Risks

- **RISK (abuse): default install is unthrottled.** `config/capell-api.php` ships `rate_limit_middleware => null` and `middleware => ['api']`. The `capell-api` limiter defined in `ApiServiceProvider::packageBooted()` is never attached unless the host sets `rate_limit_middleware` to `throttle:capell-api`. A premium "public delivery" package shipping a DB-touching endpoint (`ResolvePublicPageByUrlAction` runs `whereHasMorph` queries) with no default throttle is an availability risk. Recommend defaulting `rate_limit_middleware` to `throttle:capell-api`. — `config/capell-api.php:18-24`, `src/Providers/ApiServiceProvider.php:30-39`, `routes/api.php:27-32`
- **RISK (resource exhaustion): unbounded host-candidate site loading.** For host-based resolution, `candidateSitesForDomain()` eager-loads sites + `siteDomains` + `language` up to `max_candidate_sites` (default 50). The `does not hydrate wildcard site domains when an exact host matches` test guards the wildcard path, but a host with many wildcard-only domains and no exact match still hydrates up to the cap on every unsigned request. The 20ms render budget (`capell.json`) is plausibly exceeded on large multi-site installs; there is no test asserting the budget. — `src/Http/Controllers/ResolvePageController.php:419-447`
- **TECH DEBT (manifest accuracy): three stubbed health checks** (see §2.1). The `critical`-severity `api.v1.route` check implies route-registration verification that does not execute. This is a marketplace-trust issue: the package advertises operational guarantees it does not perform. — `capell.json:56-78`, `src/Health/ApiHealthCheck.php`
- **TECH DEBT (manifest accuracy): cache-tag mismatch** between `capell.json` `performance.cacheTags` and emitted headers (see §2.2).
- **CONTENT-VISIBILITY: boundary is correct but entirely externalized — no local regression test.** Published/enabled filtering is enforced upstream (`ResolvePublicPageByUrlAction::resolvePageUrl()` applies `->enabled()` and `applyPublicPageConstraints()`, and excludes `UrlTypeEnum::Redirect` — verified in `vendor/capell-app/core`). The API package itself has **no test** proving a draft/disabled/redirect page is not leaked through `/resolve`; it relies on core. Per the capell skill ("rendering changes need tests proving anonymous and non-admin safety"), add an API-level test that seeds an unpublished page and asserts `404`, so a future core change cannot silently regress this surface. — `tests/Feature/Http/ResolvePageControllerTest.php`
- **AUTHZ: signed-URL scope is well-tested and sound.** The `site`/`language` override requires `hasValidSignatureWhileIgnoring(['fields','include','containers'])`, the signature pins `site`+`language` while allowing those three to vary, and tests confirm an attacker cannot swap `url=/terms`→`url=/privacy` on a signed link (`does not allow signed context URLs to change the target page URL`). This is a strength — keep it. — `src/Http/Controllers/ResolvePageController.php:64-66,159-196`
- **CACHE/PUBLIC-OUTPUT SAFETY: sanitization is solid and well-tested.** Recursive Symfony HtmlSanitizer over fields, meta, layout/container meta, widget data, and widget HTML; the `includes layout html and sanitizes unsafe html strings` test exercises `onclick`, `javascript:`, `<script>`, `srcdoc`, nested payloads. `layout.html` requires bounded containers (`requestsUnboundedLayoutHtml` → `422`), preventing a "dump the whole rendered site" call. Strong. — `src/Support/SanitizesPublicHtml.php`, controller `:354-365`
- **i18n: error/message strings are not translated.** `'Page not found'`, `'Forbidden'`, `'layout.html requires explicit bounded containers.'` are hardcoded English literals. The capell skill requires user-facing strings to use translations. For a JSON API these are developer-facing, but `message` is consumer-visible; move to translation keys for consistency and localized error surfaces. — `src/Http/Controllers/ResolvePageController.php:98-111`
- **TEST GAP: rate limiter behavior, CORS, and the installed-package fallback DB query are untested.** `ApiServiceProviderTest` asserts the limiter is _registered_ and returns a `Limit`, but no test drives it to a `429`, and the `CapellExtension` fallback branch in `packageIsInstalled()` has no coverage. — `tests/Feature/Providers/ApiServiceProviderTest.php`, `tests/Feature/Http/ResolvePageControllerTest.php`
- **MINOR: dead/defensive route-file guard.** `ApiServiceProvider::configurePackage()` wraps `hasRoute('api')` in `file_exists(__DIR__.'/../../routes/api.php')`; the file is always shipped, so the guard is dead weight. — `src/Providers/ApiServiceProvider.php:25-27`

## 5. Marketplace & Selling

**Critique.** The `marketplace.summary`, `capell.json.description`, composer `description`, and `README` lead-in are all effectively the same sentence — "Public JSON delivery of published Capell page data." It states _what it returns_ but not _who it is for_ or _why it beats hand-rolling a controller_. It buries the real differentiators that are actually in the code: signed multi-site/locale context, recursive output sanitization, bounded layout-graph extraction, and contract-versioned responses. Composer keywords are generic (`capell, cms, laravel, api, json`) and miss every buyer search term (headless, JSON-API, multi-site, sanitized).

**Improved 1-sentence summary:**

> Secure, versioned read-only JSON API that serves published Capell pages — with multi-site/locale resolution, sanitized HTML output, and bounded layout payloads — to headless front-ends, edge renderers, and static-build pipelines.

**Improved 3–4 sentence description:**

> Capell API turns your published CMS pages into a clean, contract-versioned JSON feed any front-end can consume — React/Vue apps, edge functions, static-site generators, or a simple terms-and-conditions pop-up. Every response is host-resolved to the correct site and language, runs through a hardened HTML sanitizer, and carries explicit version and cache-tag headers, so authoring state, drafts, and internal models never leak to public callers. Trusted integrations can pin an exact site/language with signed URLs and pull the full bounded layout graph (containers, widgets, optional rendered HTML) for structured rendering. Public by default, hardenable with your own auth, throttle, and CORS middleware — no forking the package.

**Screenshot/media gaps.** Manifest ships **1** generic card image while `docs/screenshots.json` already plans the **4** that actually sell the product (success payload, not-found, forbidden-without-signature, layout graph). Capture those four (header panel visible) and list them in `capell.json.marketplace.screenshots`. Add a fifth: a tiny code sample showing a `fetch()` → rendered fragment, to make the headless value visceral. Also publish the OpenAPI spec (see §3) as linkable media.

**Pricing / tier / bundle positioning.** Premium tier in the `publishing-pro` bundle is defensible _only if_ the differentiators ship — today the deliverable is "one resolver endpoint", which a buyer could view as thin for premium. Strengthen the value story by completing §3 (list/changed-since endpoints, OpenAPI, ETag, CORS) so it reads as a headless-delivery layer, not a single route. Cross-sell is natural via hard deps and the README "Best Used With": bundle/upsell alongside **Layout Builder** (unlocks `include=layout`), **HTML Cache** (caching layer for these responses), and **Frontend Authoring**. Position as the "headless/omnichannel" capstone of Publishing Pro.

**Differentiators / value props / target buyer.** Differentiators: signed site+locale context that can't be tampered to repoint URLs; recursive, defense-in-depth sanitization on every field including widget HTML; bounded layout-graph extraction with an explicit anti-"dump everything" guard; versioned response contract. Target buyer: an agency/dev team running Capell as the editorial backend but rendering the experience elsewhere (Next/Nuxt, mobile, kiosk, email fragments), or embedding CMS-managed snippets (terms, banners) into a non-Capell app.

**Keywords/tags (8–12):** `headless-cms`, `json-api`, `page-api`, `multi-site`, `localization`, `html-sanitization`, `signed-urls`, `layout-graph`, `static-site-generator`, `content-delivery`, `laravel`, `capell`.
